# Phase 03 — Supabase local stack and domain schema with RLS

Read [README.md](README.md) first: its global rules, decisions and verified facts apply to every step here. Start only after phase 02 is committed.

Skills: `karpathy-guidelines`, `antislop-code`.

Steps:
1. `pnpm add -D supabase`; `pnpm exec supabase init`. In `supabase/config.toml` set: `project_id = "avenro"`; `[db] major_version = 17`; `[auth] site_url = "http://localhost:3000"`, `additional_redirect_urls = ["http://localhost:3000/auth/confirm"]`; `[auth.email] enable_confirmations = true`; `minimum_password_length = 12`; `[auth.sessions] timebox = "336h"`, `inactivity_timeout = "72h"` (carries over Nest's 14-day absolute / 3-day idle sessions); keep default `[auth.rate_limit]`; every `[auth.external.*]` provider disabled (owner decision 5 Nov 2026: email and password only, no OAuth); `[storage]` bucket `workspace-files` private, `file_size_limit = "50MiB"`.
2. Create `supabase/migrations/<ts>_domain_schema.sql` from `supabase/_extract/domain.sql` unchanged except for removing `pg_dump` session `SET` lines that Supabase migrations reject (e.g. `SELECT pg_catalog.set_config('search_path', '', false);` stays only if `db reset` accepts it).
3. Profiles: `profiles.id` equals `auth.users.id` but has no FK to `auth.users`, so deleting an auth user leaves a scrubbed tombstone and keeps teammates' history intact (FKs from domain tables to `profiles` are `RESTRICT`). Add trigger `public.handle_new_user()` (`SECURITY DEFINER`, `SET search_path = ''`) `AFTER INSERT ON auth.users` that inserts the profile; phase 04 extends it.
4. Create `supabase/migrations/<ts>_rls.sql`:
   - `alter table … enable row level security` on every public table; `revoke all on all tables in schema public from anon`.
   - Helpers, all `STABLE SECURITY DEFINER SET search_path = ''`: `private.workspace_role(ws uuid) returns public.workspace_role` (ACTIVE membership of `auth.uid()`, null otherwise, and null when the caller's profile has `onboarded_at is null` or `deleted_at is not null`); `private.is_member(ws)`; `private.can_write(ws)` (OWNER, ADMIN, MEMBER); `private.is_admin(ws)` (OWNER, ADMIN); `private.has_project_access(ws, project)` (member and project role not `CLIENT`). Put helpers in a `private` schema not exposed by the API.
   - Policy template A for every table with `workspace_id` and `project_id`: select `using (private.has_project_access(workspace_id, project_id))`; insert/update `with check (private.can_write(workspace_id) and private.has_project_access(workspace_id, project_id))`; no delete policy (archive instead, per CURRENT_STATE concern 8).
   - Exceptions: `project` (has `workspace_id` but no `project_id`: select when member and not CLIENT on that project; insert/update admin), `workspace` (select member; update admin; insert any authenticated user, owner = `auth.uid()`), `workspace_member` and `workspace_invitation` and `project_membership` (select member; write admin), `audit_event` (select admin; no client insert; written by security-definer functions only), `integration` and `webhook_delivery` (no client policies at all; server uses secret key), `notification` (select/update only own recipient column; agent confirms the column name from `domain-columns.txt`), `client_portal_item` (members via template A, plus CLIENT role may select rows whose status is published), `profiles` (select self or profiles sharing a workspace; update self only; no insert/delete from client), `storage_object` (template A).
   - Storage: policies on `storage.objects` for bucket `workspace-files` where the first path segment is the workspace id and `private.can_write`/`private.is_member` apply.
5. `supabase/tests/rls.test.sql` (pgTAP): anon reads nothing; non-member reads nothing; VIEWER reads but cannot insert; CLIENT cannot read `issue`; admin can manage members; owner-membership trigger rejects a workspace without active owner; user A cannot read user B's notification.
6. `pnpm db:start`, `pnpm db:reset`, `pnpm db:test`, `pnpm exec supabase db lint`, then `pnpm db:types` → `lib/supabase/database.types.ts`. Delete `supabase/_extract/` after the migration is committed.

Acceptance: reset applies cleanly; all pgTAP tests pass; `supabase db lint` reports no errors; `select count(*) from pg_tables where schemaname='public' and not rowsecurity` returns 0.
