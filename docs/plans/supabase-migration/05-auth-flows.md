# Phase 05 — Next.js Supabase integration and auth flows

Read [README.md](README.md) first: its global rules, decisions and verified facts apply to every step here. Start only after phase 04 is committed.

Skills: `karpathy-guidelines`, `antislop`, `antislop-code`, `antislop-copywriting` (form copy), `antislop-ui`, `vercel-react-best-practices`, `emil-design-eng`, `fixing-accessibility`, `baseline-ui`. Read `node_modules/next/dist/docs/01-app/01-getting-started/16-proxy.md`, `02-guides/authentication.md`, `02-guides/forms.md`, `02-guides/data-security.md`, `02-guides/environment-variables.md`.

Steps:
1. `pnpm add @supabase/supabase-js @supabase/ssr server-only`.
2. Env, validated with zod: `lib/env.ts` (`import "server-only"`; `SUPABASE_URL` server-side URL, `SUPABASE_SECRET_KEY`, `UNSUBSCRIBE_TOKEN_SECRET` ≥32 bytes, `SITE_URL`) and `lib/env.public.ts` (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_SITE_URL`). Use the key names `supabase status -o env` prints in the installed CLI. Update `.env.example` with placeholders and comments only.
3. Clients: `lib/supabase/server.ts` (`createServerClient`, `cookies()` getAll/setAll, URL `env.SUPABASE_URL`), `lib/supabase/client.ts` (browser, `NEXT_PUBLIC_SUPABASE_URL`), `lib/supabase/admin.ts` (`server-only`, secret key, `auth: { persistSession: false }`), `lib/supabase/proxy.ts` (session refresh helper). All four pass the same `cookieOptions.name = "sb-avenro-auth-token"`: in Docker the server and browser use different Supabase hostnames, and the default cookie name is derived from the hostname, so without a fixed name sessions break.
4. `proxy.ts` at root: refresh session with `supabase.auth.getClaims()`; matcher excludes `_next/static`, `_next/image`, images, `favicon.ico`. Redirect unauthenticated users away from `/account` and `/app`; redirect authenticated but un-onboarded users (claims → profile `onboarded_at` null, or accepted terms version older than current) to `/auth/complete-profile`. Server code must authorize with `getClaims()`/`getUser()`, never `getSession()`.
5. Server actions in `actions/auth.ts` (each validates with zod, returns `SignUpActionState`-style objects, never throws raw Supabase errors to the UI):
   - `signUpAction`: fields `name` (1–50 chars, fixes the current `<= 5` bug), email, password (12–72 chars; drop the 32-char cap), confirm password, `birth-year` (number input, no hint text about the minimum, no default), required checkbox `accept-legal` ("I agree to the Terms of Service and Privacy Policy", both linked, unchecked), optional checkbox `marketing-opt-in` (unchecked, separate, "Email me product news. Unsubscribe anytime."). If `currentYear - birthYear < 16` (treat the boundary year as under 16), return a neutral refusal, set an `age_gate=blocked` cookie for 24 h, store nothing and do not call Supabase. Otherwise call `supabase.auth.signUp` with `options.data` = `{ display_name, terms_version, privacy_version, age_confirmed: true, marketing_opt_in }` and `emailRedirectTo = SITE_URL + "/auth/confirm"`. Same generic success message for new and existing emails.
   - `signInAction` (wire the currently dead sign-in form), `signOutAction`, `signOutOtherDevicesAction` (`scope: "others"`; replaces Nest's session list), `requestPasswordResetAction` (generic response), `updatePasswordAction`, `completeProfileAction` (age gate + checkbox for API-created users and for re-accepting a new terms version; on under-16 call admin `deleteUser`, then sign out). No OAuth or social sign-in anywhere (owner decision); remove any Google button or copy.
6. Routes: `app/auth/confirm/route.ts` (`verifyOtp` with `token_hash` + `type`; email confirmation and password recovery both land here), pages `forgot-password`, `reset-password`, `complete-profile`, `check-email`. Validate `next` redirect params against same-origin paths only.
7. Pages reuse existing `Field`, `FieldLabel`, `FieldError`, `Input`, `Button`, `Checkbox` from `components/ui`, and the existing auth layout. Each page is a server component; only the form is a small client component using `useActionState`. Inputs get `autoComplete` (`name`, `email`, `new-password`, `current-password`) and `aria-describedby` errors.
8. `app/account/page.tsx` (server component) shows display name, email (from claims), sign out, sign out other devices, link to privacy settings (phase 10).

Acceptance (manual, with `pnpm db:start` + `pnpm dev`): sign-up → email in Mailpit (`http://127.0.0.1:54324`) → confirm → `/account`; profile row onboarded with two acceptances; under-16 attempt creates no `auth.users` row; unchecked legal box blocks submit server-side; reset password works; signing in with an older accepted terms version redirects to `/auth/complete-profile`.
